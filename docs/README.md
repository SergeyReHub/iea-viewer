# Документация IEA Viewer v2

Навигатор по `docs/` и правилам ведения документации в репозитории.

---

## Роли файлов

| Файл | Аудитория | Назначение |
|------|-----------|------------|
| **`README.md`** (корень) | Разработчик, DevOps | Вход в проект: запуск, порты, ссылки на ключевые документы. **Краткий**, без деталей реализации. |
| **`docs/README.md`** | Команда проекта | Этот файл: структура `docs/`, куда что класть, как обновлять. |
| **`docs/VIEWER_V2_FEATURES.md`** | Аналитик, разработчик | Спецификация возможностей и фич (что делает продукт). |
| **`docs/api.md`** | Frontend, интегратор | Контракт HTTP API. |
| **`docs/NN_*/`** | По теме | Тематические разделы с префиксом-номером (см. ниже). |
| **`docs/ТЗ/`** | Заказчик, аналитик | Постановки на отчёты/таблицы мастер-справки (`.docx`). |
| **`backend/app/metadata/descriptions/`** | UI (экран «Справочники») | Markdown-описания **конкретных таблиц БД** — не путать с `docs/`. |

**Правило:** корневой `README.md` — только то, что нужно за 5 минут поднять проект. Всё остальное — в `docs/`.

## Структура каталога `docs/`

Используем **нумерованные префиксы** (как в v1 / iea-data-structure) для сортировки и навигации:

```
docs/
├── README.md                          ← навигатор (этот файл)
├── VIEWER_V2_FEATURES.md              ← продуктовая спецификация
├── api.md                             ← API
├── 03_architecture/
│   └── multi-source.md                ← архитектура multi-DB
├── 07_database/
│   ├── iea-etl-mapping.md             ← маппинг схемы IEA (внутренний)
│   └── external-source-output-contract.md  ← ТЗ для внешнего ETL (можно отдавать отдельно)
├── 09_delivery/
│   ├── environments.md                ← окружения, CI/CD
│   └── cutover-v1-to-v2.md            ← cutover v1 → v2
└── ТЗ/
    └── *.docx                         ← постановки мастер-справки / отчётов
```

### Назначение префиксов

| Префикс | Тема | Примеры содержимого |
|---------|------|---------------------|
| `03_` | Архитектура | Компоненты, потоки запросов, границы модулей |
| `07_` | База данных | Схемы, контракты таблиц, маппинг ETL |
| `09_` | Поставка | CI/CD, окружения, деплой, cutover |
| `ТЗ/` | Постановки | Word-документы под конкретные таблицы viewer |

Новые разделы добавляйте в свободный номер (`05_testing/`, `08_security/` и т.д.), **не меняя** уже опубликованные пути без необходимости.

## Как формировать `README.md` в корне

### Обязательные блоки (поддерживать актуальными)

1. **Заголовок и одно предложение** — что за проект.
2. **Документация** — 3–6 ссылок на главные файлы + [`docs/README.md`](README.md).
3. **Быстрый старт** — Docker и/или локально, порты UI/API.
4. **Структура репозитория** — дерево верхнего уровня.
5. **CI/CD / prod** — ссылка на `09_delivery`, порты prod-хоста.
6. **Связь с v1** — один абзац (опционально).

### Чего не должно быть в корневом README

- Полный список API-методов (→ `api.md`)
- DDL таблиц (→ `07_database/` или `metadata/descriptions/`)
- История обсуждений и чеклисты cutover (→ `09_delivery/`)
- Длинные ТЗ на отчёты (→ `docs/ТЗ/`)

### Стиль

- Русский язык (как в остальном репозитории).
- Команды — копируемые блоки `bash`.
- Ссылки — относительные пути: `[текст](docs/api.md)`.
- При смене портов или prod-URL — обновить **и** README, **и** `09_delivery/environments.md`.

## Как формировать документы в `docs/`

### Именование файлов

- Тематические: `kebab-case.md` (`multi-source.md`, `iea-etl-mapping.md`).
- Спецификация продукта: `UPPER_SNAKE` допустим для одного файла (`VIEWER_V2_FEATURES.md`).
- Внешние ТЗ: говорящее имя на русском или английском (`external-source-output-contract.md`).

### Шаблон нового документа

```markdown
# Заголовок

> Кратко: аудитория, версия, дата (для нормативных ТЗ).

## 1. ...

---

*При изменении схемы/API обновите также: ссылка на связанные файлы.*
```

### Типы документов

| Тип | Признаки | Пример |
|-----|----------|--------|
| **Нормативный / внешний** | Можно отдать без репозитория; без внутренних путей к коду | `external-source-output-contract.md` |
| **Внутренний** | Ссылки на `backend/`, `config/` | `iea-etl-mapping.md` |
| **Операционный** | Команды, хосты, CI variables | `09_delivery/*.md` |
| **Продуктовый** | Фичи, экраны, out of scope | `VIEWER_V2_FEATURES.md` |

### Документы для передачи «наружу»

Если файл уходит внешнему разработчику:

1. Уберите ссылки на приватные пути репозитория.
2. Добавьте шапку: версия, дата, «единственный нормативный документ».
3. Не дублируйте — один файл = один контракт.
4. Храните каноническую копию в `docs/`; экспорт в PDF/DOCX — по запросу.

### `docs/ТЗ/` (постановки мастер-справки)

- Формат: **`.docx`** (как у заказчика).
- Имя: `ТЗ{КраткоеНазваниеОтчёта}{Контекст}.docx`.
- Содержание: структура таблицы, фильтры, период, единицы, правила топ-N / округления.
- Реализация в коде: шаблон в `backend/app/api/master_report.py` (`GUIDE_TABLE_TEMPLATES`); при новом ТЗ — обновить и docx, и шаблон.

## Описания таблиц БД (не путать с `docs/`)

Путь: `backend/app/metadata/descriptions/{domain}/{table}.md`

- Показываются в UI на экране «Справочники».
- Один файл на таблицу из `backend/app/metadata/tables.py`.
- Язык: русский, прикладной («для чего набор», «какие разрезы»).
- Источник истины по колонкам — ETL / `iea-data-structure`; viewer только описывает.

При добавлении новой таблицы в каталог:

1. Запись в `tables.py`
2. Файл `descriptions/.../*.md`
3. При необходимости — строка в `docs/07_database/iea-etl-mapping.md`

## Связь документации с кодом

| Изменение в коде | Обновить документ |
|------------------|-------------------|
| Новый API endpoint | `docs/api.md` |
| Новый экран / фича | `docs/VIEWER_V2_FEATURES.md` |
| Новый источник в `sources.yaml` | `VIEWER_V2_FEATURES.md`, при необходимости `07_database/` |
| Новый шаблон мастер-справки | `docs/ТЗ/*.docx`, комментарий в `master_report.py` |
| Смена портов / CI | `README.md`, `09_delivery/environments.md` |
| Контракт БД для внешнего ETL | `external-source-output-contract.md` |

## Чеклист при добавлении документации

- [ ] Файл лежит в правильной папке (`03_` / `07_` / `09_` / `ТЗ/`)
- [ ] Добавлена ссылка в этот `docs/README.md`
- [ ] При необходимости — ссылка в корневом `README.md` (только если документ «входной»)
- [ ] Нет дублирования с `VIEWER_V2_FEATURES.md` или `api.md`
- [ ] Внешние ТЗ не содержат внутренних путей к репозиторию
- [ ] Связанный код обновлён (или явно указано «только документация»)
